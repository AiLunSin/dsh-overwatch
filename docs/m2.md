## 0. 一句话结论

M2 的值班员闭环在**真实 Desktop DSH 子代理运行时**上跑通：根 agent 以
`mode=supervised` 编队 → L2 事件单 → 懒启动一个 `delivery:'caller'`、`maxDepth:1`
的子代理 → 串行 `agent/created` 里限制全部全局工具并注册三件套 → 子代理读案情卡、
取证据、提交 `coach` → Executor 写入 swarm `steer` 并验证 → 事件单关闭 → 交接班
→ disarm。**12/12 check pass，gate PASS**。

M2 仍未证明的是**判断质量**：本次用脚本化 provider，不是真实模型；误动作率、
成本是否 ≤5% 必须留到 M4 的真实模型 A/B。

## 1. 验证方法

`npm run m2` 会：

1. 在临时目录建一次性 `DSH_HOME`，用 headless 模板生成 `m2` profile。
2. 安装三个本地 bundle：`dsh-overwatch`、`dsh-overwatch-m2-harness`（进程内假
   swarm HTTP 服务）、`dsh-fake-llm-m2`（脚本化 provider）。
3. profile patch：`ports.origin` 指向假 swarm；写 token、subagent 容量 4、采样
   500ms、`wakeTimeoutMs: 5000`、`autopilot.throttle: false`（让 Guard 不抢在
   Watch 前面动作）、`twoSignalRule: true`。
4. 启动 headless DSH，任务文本为 `M2-ROOT`：
   - 根 agent 第一次模型请求调用 `watch_arm(mode='supervised')`；
   - 假 swarm 预算 0.81 → 两个 500ms tick 后开 `budget_pressure` L2 单；
   - Supervisor 懒启动值班员，卡片作为初始 prompt；
   - 值班员第一次请求 `watch_case`，第二次 `watch_evidence`，第三次
     `watch_decide(coach, confidence=0.82)`；
   - Executor 调假 swarm `intervene(steer)`，验证通过，事件单 `mitigated`；
   - 根 agent 等 3.5s 后 `watch_disarm`，写 `shift-0001`。
5. runner 独立重算 `watch.jsonl` 哈希链，并把假 swarm 的写入、provider 看到的
   工具表一并作为证据。

**零真实模型、零网络、零费用。**

## 3. 逐项细节

### 3.1 工具表

同一次值班员生命周期内的 4 次模型请求，provider 看到的工具表完全一致：

```json
["watch_case", "watch_decide", "watch_evidence"]
```

`watch/attach` 记录：`inherited=33`（全局）、`registered=watch_case/watch_evidence/watch_decide`。
`restrict({deny: 全部全局工具})` 在**串行** `agent/created` 监听里执行，因此第一个
模型请求之前就已生效；值班员看不到 `bash/write/subagent/swarm_*`。

### 3.2 案情卡与证据

- 卡片 ≤8KB：signals、evidenceIds、bounded snapshot（members/tasks/reviews/
  merge）、recentEvents（≤8）、allowedActions、constraints（8KB/3 calls/5s/20k）、
  固定 instructions。
- 第一次 `watch_evidence` 用卡片里的 evidence id 取到 budget evidence；
- 证据 refs 不存在时返回 `not_found`，不会让模型凭空引用。

### 3.3 决定与执行

```text
watch_decide(caseId, coach, target=swarm_run, evidenceRefs=[...], confidence=0.82)
  → Policy.validateDecision（case/action/evidence/confidence）
  → Policy.authorizeDecision（mode=supervised, autopilot）
  → Executor: intended → SwarmPort(intervene steer) → executed → verify → verified
  → Case: decisions[watch], actions[verified], closed(mitigated)
```

`coach` 的文本同时写入 `swarm/intervened` 事件；按上游契约**不保证投递成员 inbox**。

### 3.4 预算、超时、降级、交接班

- R = clamp(B × 0.05, 0, min(200k, 0.2B))；本次 B=1,000,000，R=50,000。
- 唤醒前检查 `S + estimate > R`、`maxWakes`、`maxWakesPerHour`；不够就只写
  `watch/notice`，Guard 继续。
- `wakeTimeoutMs` 超时写 `watch/wake/timeout`，事件单保持 open，Guard 继续负责；
  连续 2 次超时/错误写 `watch/degraded` 并停止唤醒。
- disarm 时先取值班员最后状态，再 dispose，最后写 `shifts/shift-0001.md` 与
  `watch/shift`，因此交接班里有 wakes/timeouts/S。

### 3.5 面板

`client.js` 新增：值班员的 state/wakes/timeouts/S/R/child session 小卡；顶部横幅
在 `supervised` 运行时切换为 "M2 watch officer armed"，guard-only 运行时保持原提示；
arm 模式选择增加 supervised。真实浏览器外观仍未验收。

## 4. 与方案的偏差 / 新发现

| 编号 | 方案原文 | 实测 | 处理 |
| --- | --- | --- | --- |
| D-M2-1 | arm 时懒启动值班员 | `startActivation` 的 `agent/created` 早于返回；此时 `namesOf()` 抛 "agent has no active runtime owner"，无法按名字认领 | **预生成 childId 并传给 `startActivation({childId})`**；`agent/created` 里按预留 id 认领，冷恢复按 childId/名字兜底 |
| D-M2-2 | 只需 `maxDepth:0` | `maxDepth:1` 才能创建（M0 D-M0-2）；孙代理靠 restrict 去掉 subagent | 维持 `maxDepth:1` + restrict |
| D-M2-3 | 值班员常驻 | `delivery:'caller'` 子代理结算后不常驻；`sendMessage` 可冷恢复 | 每案唤醒；每次 `agent/created` 幂等重施限制 |
| D-M2-4 | ports 只走 Host web server | headless 没有 webServer，无法给 M2 做真实宿主验证 | 新增 `ports.origin`（空则仍用 webServer），供 headless/CLI/外部形态使用 |
| D-M2-5 | `autopilot.pause` 控制暂停 | 该开关属于值班员建议；硬闸门有独立开关 | `autopilot.pauseOnHardLimit`（M1 已加） |
| D-M2-6 | 值班员可建议 `abort` | 只有 L4 或人类确认才允许 | Executor 用 `hardLimit = (severity==='L4')`；L2/L3 卡片不列 abort |

## 5. 未验证 / 边界

- **没有真实模型**：脚本化 provider 只证明管线、限制、预算与记录；不证明判断质量、
  误动作率、5% 成本。M4 的真实 A/B 是发布门槛。
- **没有真实 dsh-swarm**：假 swarm 只实现 M1/M2 用到的 HTTP 契约；真实市场的
  dispatch/review/merge 行为未参与。
- **冷恢复只做了单元测试**：`sendMessage` 冷恢复路径在 `test/watch.test.js` 用假
  subagents 服务验证；M0 A-2 在真实 DSH 上验证过 sendMessage 冷恢复，但 M2 的
  "第二案冷恢复"尚未在真实宿主上跑。
- **人类 resume 未提供 HTTP 路由**：值班员/Guard 的 pause 需要人恢复，目前只能
  通过后续接口或重新 arm；M3 面板动作补。
- **面板未做真实浏览器验收**；HTTP/状态契约有单元与烟测。
- **值班员证据不含上游正文**：ref 解析只返回摘要/观测值，避免把不可信正文塞进模型。
- **Windows 文件权限**只做 best-effort。
