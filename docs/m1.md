## 1. 验证方法

`npm run m1` 会：

1. 在系统临时目录建一次性 `DSH_HOME`，用
   `dsh --profile m1web --from-default-profile web --dump-config` 生成 Web profile。
2. 安装三个本地 bundle：`dsh-overwatch`（本仓库）、
   `dsh-overwatch-m1-fake-swarm`、`dsh-overwatch-m1-probe`。
3. 用 profile patch 覆盖：
   - overwatch：`mode: guard`、`http.token: m1-token`、
     `ports.swarmToken: m1-swarm-token`、采样 500ms、`autopilot.throttle: false`、
     `throttleMinutes: 1`，阈值保持默认（0.80 / 0.95）。
   - fake swarm：`token: m1-swarm-token`。
4. 启动真实 Web host（`--port 0 --no-open`），probe 用真实 HTTP 驱动：
   无 token/错 token/跨源/重复 arm → 401/401/403/409；随后把 fake swarm 的预算
   依次改成 0.81、0.96、1.01，等待事件单/动作/快照；最后 disarm。
5. probe 自己重算 `watch.jsonl` 的 `prev/hash` 链，写报告；runner 收集证据并发布。

- **零模型调用、零网络、零费用**：profile 不挂模型 provider；fake swarm 是
  loopback 上的 DSH 插件，只实现 overwatch M1 读取/写入用到的字段。
- 运行耗时约 **5.7s**（probe 阶段），临时 profile 用完即删。

## 3. 逐项细节

### 3.1 HTTP 面

| 请求 | 状态 | 说明 |
| --- | --- | --- |
| `GET /overwatch/api/health` | 200 | 服务日志、能力、run 列表 |
| `GET /swarm/api/health` | 200 | fake swarm 能力探测（arm 前置） |
| `POST /runs/swarm_m1/arm`（无 token） | 401 `UNAUTHORIZED` | 写接口拒绝 |
| 同上（错 token） | 401 | token 精确比较 |
| 同上（`Origin: https://evil.example` + 正确 token） | 403 `CROSS_ORIGIN` | 跨源拒绝先于 token |
| 同上（正确 token，`mode=guard`） | 200 | `data.state=watching` |
| 第二次 arm | 409 `ALREADY_ARMED` | 单 run 单 supervisor |
| `POST /fake/api/budget` | 200 ×3 | 测试控制面（仅 fake swarm） |
| `GET /runs/swarm_m1/cases?state=open` | 200 | 事件单列表 |
| `POST /runs/swarm_m1/disarm` | 200 | `data.state=disarmed` |
| disarm 后 `GET /runs/swarm_m1` | 200 | 从归档读取，`armed:false` |
| 再次 disarm | 409 `RUN_NOT_ARMED` | 幂等边界 |

### 3.2 事件单与动作

| 阶段 | 事件单 | 观察到的动作 | 结果 |
| --- | --- | --- | --- |
| 0.81 | `budget_pressure` L2 `open` | 无（`autopilot.throttle=false`） | 只开单 |
| 0.96 | `budget_pause` L3 | `pause` intended → executed → verified | 快照 `paused`，等人工 resume |
| 1.01 | `budget_exhausted` L4 | `abort` intended → executed → verified | 快照 `aborted`，case closed |
| disarm | 其余未决单 | — | `closeReason=abandoned` |

> 报告里的 `cases[]` 是各阶段“首次看到该单”的切片（所以 L4 的那条在动作完成前
> 采集，actions 为空）；动作事实以 `watch.jsonl` 与 `report.checks.*-watch` 为准。

### 3.3 watch 链

`e2e/m1/results/watch.jsonl`：25 条，首条 `watch/armed`，末条 `watch/disarmed`。
类型序列包含 4 条 `watch/sample`、4 条 `watch/case/opened`、2 组
`watch/action/intended|executed|verified`、3 条 `watch/case/closed`、1 条
`watch/guard/notice`。probe 用与 `src/store.js` 相同的 canonical JSON 规则重算
`sha256(prev + "\n" + body)`，全部匹配。

## 5. 与方案的偏差（已回写实现/文档）

| 编号 | 方案原文 | 实际 | 处理 |
| --- | --- | --- | --- |
| D-M1-1 | `autopilot.pause` 控制暂停 | 该开关属于值班员（M2）；硬闸门需要独立开关 | 新增 `autopilot.pauseOnHardLimit`（默认 true），`pause` 仍默认 false |
| D-M1-2 | `budget_pressure` ≥0.80 映射 L1 | M0 的信号实现是 L2，且 L2 才开单/动作 | 保持 L2，文档明确"80% = L2 软暂停阈值" |
| D-M1-3 | 阈值触发 throttle 后 10 分钟 resume | resume 由 tick 的 `dueAt` 驱动，不额外起 timer | 少一个定时器，可测试、可重启恢复 |
| D-M1-4 | arm 预留值班员槽位 | M1 不启动子代理 | guard/observe 不占槽；M2 supervised 再做「成员数 + 1」校验 |
| D-M1-5 | swarm 写 token 来自 swarm 配置 | overwatch 原本复用 `http.token` | 新增 `ports.swarmToken`，空时回退 `http.token` |
| D-M1-6 | `case detail` 时间轴可按 case 过滤 | 当前返回运行时间轴前 50 条 | 面板只用 case 的 signals/actions/decisions，避免误读 |

M0 的 D-M0-1…D-M0-7（`schemas(agent)`、`maxDepth:1`、冷恢复、`webServer` 注入、
preset、写路由自校验、fishkeeper 401）继续有效；M1 不涉及子代理，故
`maxDepth` 只在 M2 生效。

## 6. 未验证 / 边界

- **没有真实模型回合**：M1 本来就不含模型；判断质量、5% 预算是否够要 M2 实测。
- **fake swarm 不是 dsh-swarm**：只验证 overwatch 读取/写入契约，不验证真实市场、
  评审、worktree。真实 swarm 上的 arm 需要等 M2/集成环境。
- **面板没有真实浏览器验收**：client 的注册/slot/i18n/渲染烟测通过，但真实
  DSH Web 页面里的视觉、焦点、窄屏未截图验收（M0 记录 headless Edge 在本机会挂起）。
- **锁状态**：面板读 run detail 的 `lock.held`；health 列表不展开锁。
- **I-3 的自动处置**：失败连击会开 L2 单，但 guard 不做停派发/重派（那需要 M2
  值班员或人工）；这是 guard-only 的诚实边界。
- **Windows 文件权限**：只做 best-effort，不宣称 0700/0600。
- **taskkill 128**：probe 结束后 Web host 已自行退出时会出现，runner 视为正常。
