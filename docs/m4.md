## 3. 真实模型验证

### 3.1 已执行的单次唤醒（PASS）

`e2e/m4/` 用一个脚本化 root + **真实 DeepSeek account 模型**只跑**一次**值班员
唤醒，成本可控在 2 元内：

| 项 | 结果 |
| --- | --- |
| 路由 | `deepseek-account/deepseek-flash`，reasoning `off`，`maxTokens 2048` |
| 用例 | 合成 `budget_pressure` L2（81%，一个任务在飞） |
| 工具 | 真实模型调用 `watch_case` → `watch_evidence` → `watch_decide` |
| 决定 | `coach`，confidence 0.82，accepted |
| 动作链 | intended → executed → verified，action `act_40077aa4487e` |
| 用量 | 3 calls / **9,958 tokens** / 11.7s；gate 9/9 pass |
| 证据 | `e2e/m4/results/report.json`、`watch.jsonl`、`calls.json`、`llm.jsonl` |

真实模型暴露并修复了三个 bug：

1. 预算证据 id 用 `String(ref)` 生成，出现 `ev_swarm_budget_run:[object Object]:pressure`；
   模型复制这个 id 后校验失败。改为稳定 `refKey`（`runId=swarm_m4`）。
2. `watch_decide` 的 `target.kind` 只有 `string`，真实模型猜了非法值
   （`INVALID_DECISION: target.kind must be one of ...`）。改为 enum 并在案情卡
   增加 `targets` 提示。
3. 拒绝决定的事件没有记录 `errors`，无法诊断。现在 `watch/decision/rejected`
   带 `errors`。

复现：

```powershell
npm run m4:real          # 默认 reasoning=off，单次唤醒，token 上限 80k / 200s
```

它会把当前 `$DSH_HOME/.credentials.yaml` 复制到一次性 DSH_HOME（不打印、不发布），
用 `supervisor.agentOptions` 把**只有值班员**路由到真实模型；root 仍是脚本化 fake，
所以不会产生第二段真实模型费用。

> 这是“真实模型能看案情卡、按三工具决定、被执行器接受”的验证，**不是 A/B**；
> 它只能证明一次判断链路，不能证明判断质量优于 guard-only。

### 4.2 Host 401 的结论

401 不是 host bug，而是**缺少浏览器 token cookie**：`?token=` 打开宿主时，宿主把
token 写成 cookie，`/api/fishkeeper/*` 才有 200；服务端直连（无 cookie）仍是 401。
这一条同时解释了此前“fishkeeper 只在浏览器连接上可用”的现象。
