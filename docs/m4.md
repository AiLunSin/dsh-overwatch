## 2. 发布产物

### 2.1 构建

```powershell
npm run build:release      # -> dist/ailunsin--dsh-overwatch
npm run smoke:install      # 安装 dist 目录到一次性 profile
node scripts/smoke-install.mjs --package dist/.../ailunsin-dsh-overwatch-0.1.0.tgz
```

- `scripts/build-release.mjs` 重写 `package.json` name、`cordis.patch.yml` bundle
  行 name（加引号）和 `client.js` 模块 id，并逐项校验后再交付。
- `scripts/smoke-install.mjs`：临时 `DSH_HOME` + web profile →
  `dsh plugin add` → 校验 bundle 列表、安装目录、client/patch 重写。
  **目录与 tarball 两种形态均 PASS**。

`npm pack --dry-run`：

```text
name: @ailunsin/dsh-overwatch
version: 0.1.0
package size: 151.2 kB
unpacked size: 591.1 kB
total files: 46
```

### 2.2 CI

`.github/workflows/ci.yml`：Ubuntu/Windows/macOS × Node 22/24 跑
`check-syntax` + `npm test` + `npm pack --dry-run`；另有一个 release-build job
构建 scoped 副本并上传 artifact。真实 DSH e2e 不进 CI（需要 Desktop 安装）。

### 2.3 发布阻塞

| 项 | 状态 | 原因 |
| --- | --- | --- |
| `npm publish @ailunsin/dsh-overwatch` | ⛔ EOTP | 已实际执行；npm 要求一次性密码，附浏览器认证 URL；`npm view` 404 确认尚未发布 |
| Git tag `v0.1.0` | ✅ 本地 | 指向 M4 提交；无 remote，无法 push |
| GitHub Release | ⛔ | 仓库没有 `origin`；本机没有 `gh` |
| npm 包名 | ✅ 未被占用 | `npm view` 404 |

发布步骤（需要 OTP）：

```powershell
cd dist/ailunsin--dsh-overwatch
npm pack
npm publish --access public        # 输入当前 6 位 OTP
npm view @ailunsin/dsh-overwatch version
```

## 3. 真实模型 A/B（未执行）

### 3.1 预注册协议

| 组 | 配置 | 目的 |
| --- | --- | --- |
| A | 无监管 | 基线 |
| B | `mode=guard` | 硬闸门价值 |
| C | `mode=supervised` | 值班员增量 |

场景：I-1（预算悬崖）、I-3（失败循环）、I-4（成员空转），各重复 3 次，
至少 2/3 视为通过。
指标：任务通过率、墙钟、token、检测延迟、误动作数、人工介入、复盘时间、
值班员成本占比。
假设：H1 B 比 A 少 0 超支；H2 C 比 B 在 ≥3 场景更快恢复/更少人工；
H3 C 的 token 成本比 B 高 ≤5%。

### 3.2 为什么没跑

- 本机 `DEEPSEEK_API_KEY` 等环境变量不存在；Desktop 的模型凭据属于用户
  profile，不在临时 profile 中可用。
- A/B/C 会真实消耗模型 token（每个场景多次成员/评审/值班员调用）。在没有
  明确费用额度和模型凭据的情况下执行会越过授权边界。
- 需要真实 dsh-swarm 市场/评审/合并；现有 e2e 用假 swarm，只能验证契约。

### 3.3 执行入口

使用真实 provider 的临时 profile，重复 3×3 场景，记录 `watch.jsonl`、
swarm `report.csv`、pressure 回执；按上表计算。命令模板见
`docs/m2.md` 的 profile patch 与 `e2e/` runner。运行前需要用户提供：

1. 可用的模型凭据（或被允许使用现有 desktop profile）；
2. 单次 A/B/C 的费用上限；
3. 真实 swarm 仓库与任务卡。

## 4. 浏览器 / 恢复演练（阻塞）

- fishkeeper 恢复只在浏览器连接上可用；本机没有可自动化的浏览器
  （M0 记录 headless Edge 挂起）。
- 面板恢复流程（dryRun → 确认 → 执行 → `/restores` 记账）有 fake fetch
  渲染烟测；`confirmToken` 不落 storage/URL/日志。
- 恢复演练清单：安装 fishkeeper + 种子数据 → 在面板选检查点 → 预检 →
  确认 → 观察 pre-restore 安全检查点 → 结果行 → `watch/restore/result`。
  需要在真实浏览器手工执行并截图。
