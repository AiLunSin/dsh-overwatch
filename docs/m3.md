## 2. 实现

### 2.1 鱼缸只读索引（Host）

fishkeeper 的写路由在 `ctx.connection.fetch`（浏览器面），Host 不可写；因此
overwatch 只读其数据目录：

```text
~/.dsh/fishkeeper/                    # fishkeeper 默认；可用 config.fish.dataDir 覆盖
├── checkpoints/<sourceId>/index.jsonl
├── checkpoints/<sourceId>/<ck>/manifest.json   # 只读 pinned/totals/files 摘要
└── audit/<sourceId>.actions.jsonl              # restore/pin/delete 审计尾部
```

- 只读 `id/createdAt/trigger/files/storedBytes/logicalBytes/pinned`；
  不读 blob、不读日记正文。
- 坏行/坏 manifest 记入 `errors`，不中断其他源。
- 默认根是 `~/.dsh/fishkeeper`（fishkeeper 自己的默认），**不是** `$DSH_HOME`；
  这是对技术方案 §4.3.2 的修正。可用 `fish.dataDir` 指到别的目录。

API：

```http
GET /overwatch/api/fish
GET /overwatch/api/fish/:sourceId
```

### 2.2 合并时间轴

`GET /overwatch/api/runs/:id/timeline?since=<opaque>&limit=`：

- 源：swarm 事件、pressure 采样（Probe 每 tick 记录，≤500 条）、watch 事件。
- 排序：`(at, sourceRank, seq)`，固定 `swarm < pressure < fish < watch`。
- 游标：首次 `since=0`；之后原样回传 `nextSince`（`at|rank|source:seq`）。
- 归档 run 仍有 `since` 游标（只有 watch 事件）。
- 不做跨源正文复制，只有摘要与计数。

### 2.3 doctor

`GET /overwatch/api/doctor`（只读）：

| check | 说明 |
| --- | --- |
| `data-dir` | 写一个临时文件并删除 |
| `service-log` | 服务链校验 |
| `write-token` | 是否配置（warn 不是 fail） |
| `swarm` | Port health（fail） |
| `pressure` | Port health（warn） |
| `fishkeeper-write` | Host 401 时 warn，并注明 browser-authenticated |
| `fish-index` | 只读索引可用性/坏行 |
| `run:<id>` | 每个运行锁/链/值班员状态 |
| `disk-free` | <200MB warn |

### 2.4 恢复记账（不碰令牌）

浏览器执行 fishkeeper 恢复，overwatch 只记账：

```http
POST /overwatch/api/runs/:id/restores   # x-overwatch-token
{ sourceId, checkpointId, phase: 'intent'|'result',
  files?: [{path,action,stale,bytes}], warnings?: [], result?: {ok,files,error} }
```

- 任何层级出现 `confirmToken` → 400 `RESTORE_TOKEN_REJECTED`；
  overwatch 不接收、不存储、不代理令牌。
- 写入 `watch/restore/intent` / `watch/restore/result`（actor=human）。
- 恢复前 fishkeeper 自行创建 `pre-restore` 检查点；代码回滚走 git。

## 3. 面板（M3）

`client.js` 新增：

- **鱼缸** tab：宿主索引（源、检查点、audit），fishkeeper 浏览器面可用时展示
  overview/checkpoints；恢复流程 = dryRun 预检 → 展示 files/warnings → 二次确认 →
  执行 → 逐文件结果；每一步通过 `/restores` 记账。
- **回放** tab：合并时间轴，source chip、5s 轮询、隐藏暂停、`nextSince` 分页。
- doctor checks 在完整性卡中展示。
- a11y：tablist 键盘、恢复对话框 focus trap/Esc、表格 caption、状态文字+颜色。
- 所有可见文案 zh/en 对称；confirmToken 只在组件内存中。

> 面板没有在真实浏览器里人工验收；JS 语法、静态契约与 fake React 渲染烟测通过。

## 4. 未验证 / 边界

- **真实恢复演练 BLOCKED**：fishkeeper 的 `POST /checkpoint/restore` 在
  `ctx.connection.fetch`，需要浏览器认证；Host fetch 401（M0 A-5）。
  面板可以走浏览器面，但本环境没有可自动化的浏览器（headless Edge 在本机会挂起）。
- **真实 fishkeeper 数据未参与**：e2e 用临时目录里的 index/manifest/audit fixture；
  只验证了读取格式与容错。
- **时钟/未知时间**：时间轴只排有 `at` 的条目；未知时间排序规则留给面板/ M4。
- **恢复超时/取消**：浏览器侧由 fishkeeper 处理；overwatch 只记录结果。
- **i18n/a11y**：静态与烟测通过，真实键盘/屏幕阅读器未人工验收。
